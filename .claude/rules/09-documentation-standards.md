# Documentation & Commenting Rules

> **[🤖 AI AGENT INSTRUCTIONS]**
> Follow these standards when writing comments and project documentation.

1. **Self-Documenting Code:** Write clean, descriptive code so that variable and function names explain *what* they do. Use comments only to explain *why* a complex decision was made.
2. **JSDoc / Docstrings:** Public functions, classes, and complex utility methods must include clear documentation comments detailing parameters and return types.
3. **Update Docs on Changes:** If an architectural change or API contract is modified during coding, remind the user to update the corresponding markdown file in `docs/`.
